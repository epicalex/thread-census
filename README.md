# Just one more thread

A static, unofficial celebration of Lenny’s follow-up questions. No framework, install step, analytics, external fonts, or runtime data requests.

## Publish on GitHub Pages

Copy `index.html`, `style.css`, `script.js`, `favicon.svg`, `favicon.ico`, `apple-touch-icon.png`, `social-card.png`, `yarn-ball.svg`, and `.nojekyll` to the publishing folder of your GitHub Pages repository. All asset paths are relative, so project URLs work. Include all of these assets when publishing.

The finished HTML includes all data; opening `index.html` locally also works. JavaScript adds search, the pull/follow filter, and the resize Easter egg. Width changes trigger the wool animation after a brief pause; height-only changes do not. Reduced-motion preferences disable the animation. The hero and resize animation share `yarn-ball.svg`, regenerated by `build.py` from `hero_yarn.py`.

For an incremental refresh, list the complete archive manifest with MCP `list_content`, compare filenames with `data/thread-results.json`, and retrieve only previously unseen filenames using `read_content`. Keep those transcript files and a new-entries-only `index.json` outside this public repository. Run the original counter against that private directory, review all candidates (including exclusions), and rerun until there are no pending reviews or parse errors. Then merge using:

```sh
python3 refresh_new.py --results /path/to/private/new-results.json --manifest /path/to/private/full-manifest.json
python3 build.py
node render-assets.mjs
```

`refresh_new.py` accepts the full MCP listing (`results` and `total`) or an `index.json` with `podcasts`. It rejects missing archive entries, duplicate filenames, incomplete reviews, and batches that differ from the exact set of new filenames. It preserves existing episode/event records and combines reviewed counts. Add new editorial assignments to `data/thread-themes-review.json` before building, and keep the coverage notes and yearly wording counts in `template.html` aligned with the run. No raw transcript text or full candidate audit is copied to public results.

From the original project workspace, rerun the archived analysis and then regenerate this page:

```sh
python3 outputs/count_threads.py --repo work/full-archive --review outputs/full-archive/thread-review.json --out outputs/full-archive --source mcp
python3 outputs/full-archive/analyse_themes.py
python3 thread-census/build.py
```

`build.py` uses the reviewed results in `data/thread-results.json`. Edit `template.html` for page copy and layout, then regenerate. If refreshing the underlying archive, review new candidates first, and update the snapshot date and coverage notes in the template to match the new run.

## Build this repository

Run `python3 build.py` from the repository root. The data folder contains derived metadata, counts and paraphrased summaries; it contains no raw transcripts. The archive recount commands above refer to the original analysis workspace.

## Favicon and sharing card

The yarn favicon has SVG and 16/32/48px ICO versions, plus a 180px Apple touch icon. The 1200 × 630 PNG sharing card uses the site’s peach palette, woven yarn and reviewed headline count. Open Graph and Twitter metadata in `template.html` point to the GitHub Pages URL; change those absolute URLs if moving the site.

Edit `favicon.svg` or `social-card-template.svg`, then rebuild:

```sh
python3 build.py
# One-time image tooling setup (Node.js required):
npm install --no-save --package-lock=false playwright sharp
npx playwright install chromium
node render-assets.mjs
```

Rerun both build commands after data refreshes so the card’s count and snapshot date stay aligned with the page. Commit the generated `social-card.png`, `favicon.ico` and `apple-touch-icon.png`; visitors need no image tooling. `social-card.svg` is the generated editable vector card. Link previews update after publishing, subject to each service’s preview cache.
